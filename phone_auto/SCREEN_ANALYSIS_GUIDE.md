# 폰 화면 분석 가이드 (필수 원칙)

> **모든 폰 화면 OCR/클릭 자동화 작업의 절대 규칙.**
> 이 원칙 위반 시 OCR false positive, 잘못된 좌표 클릭, 카드 잠금 등 심각한 결과 발생.

---

## 핵심 원칙 — "전체 캡쳐 → 영역 파악 → 타깃만 처리"

**금지**:
- ❌ 화면 어디에 키패드/PIN dot/입력란이 있는지 가정하고 바로 OCR
- ❌ 다른 카드에서 쓴 ROI 를 그대로 다른 카드에 재사용
- ❌ "보통 하단에 있음" 같은 휴리스틱으로 ROI 하드코딩

**필수**:
- ✅ 매 새 화면 (카드사 / 결제 단계 / 앱) 마다 **먼저 전체 캡쳐 + 영역 분석**
- ✅ 키패드 / PIN dots / 버튼 / 카드 그래픽 / 헤더 / 광고 등 **각 영역의 y 좌표 파악**
- ✅ **타깃 영역만 ROI 로 한정** → 다른 영역의 숫자가 false positive 되지 않도록
- ✅ 카드/화면별 preset 등록 (`KEYPAD_PRESETS` 등)

---

## 왜 이게 중요한가 — 실제 사례

폰 화면에는 OCR 가 잡아낼 수 있는 숫자가 **여러 영역**에 분포:

| 영역 | 예시 | OCR 가 잡으면 |
|---|---|---|
| 키패드 셀 | "0~9" | ✅ 원하는 대상 |
| PIN dots row | "○○○●●●" | ❌ 일부 엔진이 "0" 으로 오인 |
| 결제 금액 | "26,000원" | ❌ "26000", "2", "6" 등 false positive |
| 카드 번호 | "VISA 420*" | ❌ "420" 등 |
| 카드 그래픽 | 신용카드 디자인의 숫자 | ❌ 카드면의 "1234" 등 |
| 헤더 / 광고 | "10%적립" 같은 % | ❌ "10" 등 |
| QR 코드 | 패턴 | ❌ 가끔 숫자처럼 인식 |
| 하단 안내 텍스트 | "결제 비밀번호를 잊으셨나요?" | ❌ 글자 일부를 숫자로 |
| iPhone 홈 인디케이터 | 가로 바 | ❌ "0" 으로 오인 (실제 발생) |

ROI 없이 전체 이미지 OCR 시:
- 키패드 안의 진짜 "0" 이 1엔진만 잡고
- 다른 영역의 "0" 모양이 3엔진 잡으면
- 잘못된 위치가 채택 → 클릭 시 엉뚱한 곳 누름 → **PIN 입력 실패 / 카드 잠금**

## 표준 작업 절차

### 1. 새 화면 등장 시 — 캡쳐 + 분석 (필수)

```python
from phone_auto.ocr_keypad import capture_frame
path = capture_frame(cam_idx=0, warmup_frames=15)
# 시각 검토 — 어디에 키패드, 어디에 다른 정보가 있는지 손으로 확인
```

### 2. 영역 분포 분석

```python
# 모든 엔진의 digit detection 위치 (y bucket) 분포 출력
# → 키패드 row 들의 y 좌표 = 가장 dense 한 구간
# → 다른 영역의 y 좌표 = 분리 가능
```

### 3. ROI 좁히기

- 키패드의 첫 row 시작 y → ROI top
- 키패드의 마지막 row 끝 y → ROI bottom
- 마진 약간 (±5%)
- **PIN dots row + 헤더 + 카드 그래픽 + 광고 모두 제외**

### 4. ROI 검증

- `vote_digits(image_path, roi_y_frac=(top, bot))` 실행
- annotated PNG 로 시각 확인 — 모든 디지트가 키패드 셀 중앙에 마킹됐는지
- false positive (키패드 외 위치) 있으면 ROI 더 좁힘

### 5. 셔플 다양성 검증 (셔플 키패드의 경우)

- 같은 카드 화면 3~5회 셔플 후 캡쳐
- 매번 10/10 정확 매핑 + 셀 중앙 마킹 확인

### 6. preset 등록

```python
KEYPAD_PRESETS["card_name"] = {
    "flip_h": False,
    "roi_y_frac": (top, bot),
    "layout": "fixed_3x4" 또는 "shuffled_3x4" 또는 "shuffled_4x3_with_logos",
    "n_digits_pin": 6 또는 7,
    "description": "...",
}
```

## 카드/화면별 위치 차이 — 실측 데이터

같은 카메라/폰 위치에서도 **앱마다 키패드를 다른 위치에 표시**한다:

| 화면 | 키패드 y 범위 | y_frac |
|---|---|---|
| 현대 7자리 코드 | y~687~960 | (0.59, 0.95) |
| 현대 PIN 6자리 | y~762~1000 | (0.74, 0.99) |
| 하나 7자리 코드 | y~701~978 | (0.50, 0.95) |
| 하나 PIN 6자리 | y~762~903 | (0.70, 0.95) |
| NH 7자리 코드 | y~340~700 (화면 상단!) | (0.28, 0.65) |

→ NH 는 다른 카드와 정반대 — 화면 **상단**에 키패드. 절대 다른 카드 ROI 재사용 X.

## 자동화 시 필수 체크리스트

매 새 카드/화면 작업 시:

- [ ] 전체 영상 캡쳐 + 시각 검토
- [ ] 키패드 외 다른 영역의 숫자 정보 식별 (PIN dots / 금액 / 카드번호 / 광고 등)
- [ ] 키패드 영역의 정확한 y_frac 측정
- [ ] ROI 적용 OCR → annotated 시각화로 검증
- [ ] 셔플 2~3회 추가 검증 (셔플 키패드)
- [ ] preset 등록 후 caller 에 명시 (`vote_digits_for_card("card_name")`)
- [ ] caller 가 다른 카드/화면 ROI 사용 안 하도록 unit test 또는 검증
