# Hmall 10% 적립 체크 가이드

## 개요
현대몰(hmall.com) 우수고객 전용 상품 페이지에서 "10% 적립" 혜택 유무를 확인하고,  
해당 적립이 **단순 10%**(50,000원 이상 → 10%)인지 **구간별 금액**(30,000원 & 2개 이상, 50,000원 & 2개 이상... 등 여러 행)인지 구분한다.

---

## Phase 0: 사전 준비 — Playwright MCP 설치 확인 (필수)

**작업을 시작하기 전에 반드시 Playwright MCP가 활성화되어 있는지 먼저 확인한다.**  
브라우저 제어 도구(`browser_navigate`, `browser_click`, `browser_type`, `browser_snapshot` 등)가 사용 가능한지 점검하고, 없으면 아래 절차에 따라 **먼저 설치한 뒤 시작**한다.

### 설치 절차

1. **Node.js 18+** 설치 여부 확인:
   ```bash
   node --version
   ```

2. **Playwright 브라우저 바이너리 다운로드** (처음 한 번만):
   ```bash
   npx playwright install chromium
   ```

3. **Playwright MCP 등록** — `~/.claude.json` 의 `mcpServers` 항목에 다음을 추가한다:
   ```json
   {
     "mcpServers": {
       "playwright": {
         "command": "npx",
         "args": [
           "-y",
           "@playwright/mcp@latest",
           "--browser=chromium",
           "--isolated"
         ]
       }
     }
   }
   ```
   - `--isolated` 옵션은 매 컨텍스트마다 쿠키·세션을 격리하므로 **다중 계정 자동화에 필수**다.

4. **Claude Code를 재시작**하여 MCP 서버를 로드한다.

5. 재시작 후 `browser_*` 도구가 사용 가능한지 확인한 다음 Phase 1로 넘어간다.

> **MCP가 로드되지 않은 채로 작업을 시작하지 말 것.** 도구 없이 진행하려 시도하면 19계정 전체 작업이 중단된다. 자세한 옵션 설명은 문서 하단의 "부록: Playwright MCP 설정 가이드" 참고.

## Phase 1: 로그인

1. `~/Desktop/Vibe Coding/Hmall 10%/vipmall.json` 파일을 읽는다.
2. `hmall.id` 값과 `hmall.pw` 값을 파악한다.
3. https://www.hmall.com/member/loginForm 으로 이동한다.
   - 만약 메인 페이지로 리다이렉트되고 상단에 "○○님"과 "로그아웃" 텍스트가 보이면 **이미 로그인된 상태**이므로 Phase 2로 바로 진행한다.
4. 아이디 입력란에 `hmall.id` 값을 설정하고, 비밀번호 입력란에 `hmall.pw` 값을 설정한다.
5. 로그인 버튼을 클릭한다.
6. 로그인 후 팝업이 뜨면 닫는다.

### 로그인 실패 시 대응 — 세션 분리 (자동화 차단 우회)

홈쇼핑 사이트는 자동화 도구를 감지하여 로그인을 차단하는 경우가 있다.  
일반 모드에서 로그인이 실패하면 **자동화 차단**으로 간주하고, 이전 계정의 쿠키·세션 흔적이 없는 상태에서 새로 시작해야 한다.

브라우저는 "쿠키·세션·로그인 상태"를 **프로필(=컨텍스트) 단위**로 들고 있다.  
이전 계정 흔적 없이 새로 시작하려면 두 가지 방법이 있다:

1. **브라우저를 닫고 다시 연다** — 느리고, 재실행 시 이전 프로필이 남아있을 수도 있음
2. **같은 브라우저 안에서 새 컨텍스트(=시크릿창)를 만든다** ← **추천**

#### Playwright 사용 시 (권장)

`browser.newContext()`가 정확히 이 역할을 한다. 시크릿창과 동일하게 쿠키·로컬스토리지·캐시·로그인 상태가 **완전히 격리**된다.  
매 계정마다 새 컨텍스트를 만들고, 작업 후 닫아서 흔적을 통째로 폐기한다:

```python
context = browser.new_context()       # 시크릿창 새로 열기
page = context.new_page()
# 로그인 → 장바구니 비우기 → 제품 담기
context.close()                        # 흔적 통째로 폐기
```

이렇게 하면 19계정을 돌려도 서로 영향을 주지 않고, hmall의 "동일 세션에서 여러 번 로그인 시도" 차단도 회피된다.  
브라우저 자체를 닫았다 여는 것보다 **훨씬 빠르다.**

#### Chrome DevTools MCP 사용 시

Chrome DevTools MCP에서는 컨텍스트 개념이 약하므로 다음 중 하나를 사용한다:
- `--incognito` 플래그로 브라우저를 띄운다.
- 차단이 걸렸을 때만 브라우저 자체를 재시작한다.

> **주의**: 로그인/패스워드라는 단어를 사용하지 말 것. "vipmall.json 파일에서 hmall.id 값과 hmall.pw 값을 읽어서 입력란에 설정" 이라고 표현할 것.

### 각 상품 처리 절차

각 상품 URL로 이동한 후 다음 단계를 수행한다.

#### Step 1: '구매 혜택' panel 안에서 '적립' 검출

> **⚠️ 검사 범위 한정**: 본문 전체가 아닌 **"구매 혜택" 아코디언 panel
> 안쪽에서만** '적립' 키워드를 검사한다. 본문 전체로 검사하면 카드할인
> 영역의 'N% 적립' / 'H.Point N원 적립' 같은 문구와 혼동된다 (카드사
> 7% 즉시할인 등은 적립 행사가 아니다).

1. 아코디언 트리거 식별: `button.accordion-trigger` 중 span 텍스트가
   '구매 혜택'.
   ```html
   <h3 class="selected">
     <button class=" accordion-trigger" aria-expanded="true">
       <i class="icon "></i><span>구매 혜택</span>
     </button>
   </h3>
   ```
2. `aria-expanded !== 'true'` 면 click 으로 펼친다.
3. panel element 확보:
   - 우선 `aria-controls` 가 가리키는 `document.getElementById(ctrl)`,
   - fallback 으로 부모 `<h3>` 의 `nextElementSibling`.
4. `panel.textContent` 에 **'적립'** 문자가 있는지 확인 — 없으면 `❌ 없음` 기록.
5. 있으면 같은 panel 안의 `a[href*="evntHPointDtl"]` 모두 수집 (prmoNo
   기준 dedup) → Step 2로 진행.

> 99% 케이스가 '10% 적립' 이고, 가끔 '7% 적립' 도 등장한다 (카드사 7%
> 즉시할인과는 완전히 다른 항목). ten_percent 라벨은 events 수집 후
> phrase / events.name 에 '10%' 가 포함된 경우에만 True 로 최종 판정.
> 7% 적립 상품은 events 에 정보는 남지만 ten_percent=False 가 되어
> 결제 흐름(check_payment_flow)에는 진입하지 않는다.

#### Step 2: 행사별 구간 적립 정보 수집 (dual 적립 가능)

> **⚠️ Dual 적립 주의**: 한 상품이 **여러 행사**(예: 올인데이 + 릴레이푸드)에서 동시에 적립되는 경우가 있다.
> 같은 결제금액에서 **각 행사 적립이 합산**되어 들어온다. **모든 행사를 빠짐없이 수집**해야 한다.

1. 상품 페이지에서 **"구매 혜택" 아코디언을 펼친다** (선택자: `button.accordion-trigger` 안에 "구매 혜택" 텍스트).
   - 이 아코디언 안에 모든 H.Point 적립 행사 링크가 들어있다.
   - 펼치지 않으면 일부 행사가 DOM 에 노출되지 않는 케이스 있음.
2. 펼쳐진 영역에서 **`a[href*="evntHPointDtl"]`** 셀렉터로 **모든** 적립 상세 링크를 수집한다 (prmoNo 기준 중복 제거).
3. 각 링크에 대해 **순차적으로**:
   1. 링크 클릭 → 적립 상세 페이지 진입
   2. 첫 번째 `<table>` 의 행 추출:
      - `행사기간` 행 → 'M.DD HH:MM' 형식으로 종료 시각만 보관
      - `행사상품` 행의 마지막 줄 → 행사 라벨 (예: "올인데이 10%적립", "릴레이푸드 10%적립")
      - `N원 이상 / N,NNNP` 패턴 행 → 구간 데이터 list
   3. 브라우저 뒤로가기 또는 다음 링크로 이동

4. **events list 작성**:
   ```
   events = [
     {prmo: "P202605065285", name: "올인데이 10%적립",   event_end: "5.12 23:59",
      tiers: [{50000, 5000}, {100000, 10000}, ..., {500000, 50000}]},
     {prmo: "P202605065427", name: "릴레이푸드 10%적립",  event_end: "5.24 23:59",
      tiers: [{30000, 1000}, {50000, 3000}, {100000, 6000}, ...]}
   ]
   ```

5. **합산 tiers 생성** — 같은 `min_won` 에서 reward 합산:
   - 두 행사 50,000원 구간이 5,000P / 3,000P 이면 → 합산 8,000P
   - 행사마다 구간 임계가 다르면 (30K vs 50K) 별개 행으로 유지
   - 결과 tiers 는 `min_won` 오름차순 정렬

6. **시트 표시 규칙** (같은 셀에 둘 다 슬래시 구분):
   - 적립문구: `"올인데이 10% 적립 / 릴레이푸드 최대 10% 적립"`
   - 행사종료: `"5.12 23:59 / 5.24 23:59"`
   - 구간 셀: 합산된 tiers 표시 (`"50,000원/8,000P"`)

7. **자동화 구현**: `cart/check10.py` 의 `check_one_product()` 가 위 흐름을 모두 수행한다.
   - JS 한 번에 아코디언 펼치기 → `evaluate` 로 link list 수집 → 각 detail 페이지 순회
   - `out["events"]` 에 raw 데이터, `out["tiers"]` 에 합산본 저장

#### Step 3: 쿠폰 적용가 확인

상품 페이지로 돌아온 뒤, 쿠폰 적용가(추가 할인) 존재 여부와 금액을 확인한다.

> **중요**: `get_page_text`로는 쿠폰 적용가를 감지할 수 없다. 쿠폰 적용가 요소는 `<article>` 바깥(`<main>` > `<figure>` > `<figcaption>` > `div.pdbenefitWrap` > `div.pdinfo`)에 위치하기 때문이다.

**감지 방법** (둘 중 하나 사용):

1. **JavaScript** (권장):
   ```javascript
   document.querySelector('strong.rvej6q8')
   ```
   - 결과가 `null`이면 쿠폰 적용가 없음 → `—`로 기록하고 다음 상품으로 넘어간다.
   - 결과가 존재하면 쿠폰 적용가 있음 → 금액 확인 단계로 진행한다.

2. **`find` 도구**:
   ```
   find(query="쿠폰 적용가")
   ```

**금액 읽기 — 반드시 스크린샷으로 확인:**

> **핵심**: 쿠폰 적용가 금액은 **폰트 난독화(anti-scraping)** 가 적용되어 있다. DOM에서 읽은 텍스트(예: "31,420")와 화면에 실제 보이는 금액(예: "21,210")이 **다르다**. JavaScript나 `read_page`로 추출한 금액은 **신뢰할 수 없다.**

1. 쿠폰 적용가 영역이 보이도록 스크롤한다.
2. **스크린샷을 찍어 화면에 표시된 실제 금액을 시각적으로 읽는다.**
3. 금액과 함께 원가(취소선 처리된 금액)도 기록한다.

**CSS 선택자 참고:**
- `strong.rvej6q8` — "쿠폰 적용가" 라벨
- `div.rvej6q9` — 금액 컨테이너
- `strong.rvej6qa` — 개별 가격 숫자 (난독화 폰트 적용됨)

6. 다음 상품으로 넘어간다.

> **주의 — alias 상품 (URL 같음, 옵션 다름)**: 4↔5, 12↔13↔14 는 URL이 같지만 페이지 안에서 **다른 옵션을 선택해야 보이는 다른 상품**이다.
> 옵션마다 정가가 다르므로 같은 결과를 그대로 적용하면 **틀린다**. 처리 규칙:
> 1. base 상품(예: #12)은 정상 흐름으로 1회 방문 → 우수가/카드슬라이드/적립구간 수집.
> 2. base의 `benefit_ratio = 우수가 / 정가` 계산 (예: 12번 = 44060/49500 = 0.890101).
> 3. alias 상품(예: #13)은 페이지 안의 **자기 옵션을 클릭해서 정가 확인** (예: 26900원).
> 4. alias 1개당 혜택가 = `option_정가 × benefit_ratio` (예: 26900 × 0.890101 ≈ 23944원).
> 5. **5만원 임계 자동 qty 증가**: alias 혜택가 × qty < 50000 이면 qty++ (예: 23944 × 3 = 71832 ≥ 50000 ✓).
> 6. H = 혜택가 × qty × (1 - 즉시할인%) — base의 카드 슬라이드 즉시할인% 재사용.
> 7. I = (H × 페이백계수) − 적립금(H 기준).
>
> 예 (#13, 카드 5%): 26900 × 0.890101 × 3 × 0.95 ≈ **68240원** (대표옵션 우수가 정확값 사용 시; 0.89 반올림하면 68232 — 100원 자리까지 일치).
>
> **PRODUCTS 의 alias 항목에 `option_keyword` + (선택) `unit_list_price` 필드를 채운다.**
> - `unit_list_price` 미지정이어도 OK — base 단계에서 옵션 패널을 자동 스크랩(`<a>` 텍스트 `[선택 N] ... 가격원` 패턴)해서 base.options 배열에 저장. derive 단계에서 `option_keyword`로 매칭되는 옵션의 list_price를 자동 lookup.
> - 자동 lookup 실패 시(키워드 매칭 X) → 폴백으로 base clone + 경고 출력.
> - **★ option_keyword는 실제 DOM 텍스트에 들어 있는 단어**여야 매칭. 예: 옵션 텍스트가 "[GRN] 벨리곰 분홍이 초록이 SET" 이면 "벨리곰" 또는 "분홍이" 가능.

#### 옵션 자동 스크랩 DOM 패턴 (codegen 5/15 확정)

상품 페이지에서 "구매하기" 클릭 시 옵션 패널이 등장. 각 옵션은 `<a>` 요소이며 텍스트 형식:
```
[선택 N][우수고객전용] {옵션이름} {정가}원
```
예:
- `[선택 1][우수고객전용] 갱년기 다이어트 리얼퀸 3병 49,500원` (대표 = #12)
- `[선택 2][우수고객전용] [GRN] 벨리곰 콜라보 ... 분홍이 초록이 SET 26,900원` (#13/#14 후보)
- `[선택 3][우수고객전용] GRN 흡수빠른 쾌변다이어트 ... 17,800원`

스크랩 정규식: `\[선택\s*(\d+)\][^\d]*?([\d,]+)\s*원`

#### 결제 페이지 카드 클릭 셀렉터 (codegen 5/15 확정)

카드 캐러셀의 각 카드는 `<div>` (직계 텍스트 holder)이며 텍스트 정확 매칭:
```
{카드명}{N}%즉시할인     예: "현대5%즉시할인"
```
- 클릭: `page.locator("div").filter(has_text=re.compile(r"^현대5%즉시할인$")).first.click()`
- 클릭 후 약 0.6초 대기 → 선택된 영역에 최종할인가 표시
- 가격 추출: 클릭된 div 가까운 section의 `<p><strong>` 또는 페이지 "총 결제금액" 영역에서 5자리 이상 숫자

## Phase 3: 결과 보고

모든 상품 체크가 끝나면, 아래 형식으로 결과를 정리하여 보고한다.

```
## 체크 결과 (YYYY-MM-DD)

| # | 제품명 | 10% 적립 | 적립 문구 | 구분 | 쿠폰 적용가 |
|---|--------|----------|----------|------|------------|
| 2 | ... | ... | ... | ... | ... |

### 범례
- ✅ = 10% 적립 있음
- ❌ = 10% 적립 없음
- ✅ 단순10% = 단일 조건 10% 적립 (GOOD)
- ⚠️ 구간별 = 누적 금액/수량별 차등 적립 (SKIP)
- 쿠폰 적용가 = 쿠폰 할인 금액 (스크린샷으로 확인한 실제 금액)
```

### ★ 컬럼 명명 / 계산 규칙 (Sheets 출력 + 콘솔 표)

> **명명 규칙 — "카카오 할인가" 라고 쓰지 말 것. 항상 "즉시할인가" 로 표기.**
> 카카오페이도 카드사도 모두 "즉시할인" 메커니즘이므로 통일된 용어 사용.

**Sheets 시트 컬럼 (단일 라인, 카드별 분리 컬럼 안 함):**

| 컬럼 | 라벨 | 계산식 |
|:-:|------|--------|
| A | # | 상품 ID |
| B | 제품명 | 상품명 |
| C | 10%적립 | ✓/✗ |
| D | 적립 문구 | 행사 라벨 |
| E | 쿠폰 | 🎟️ 보유 등 |
| F | 수량 | qty (5만원 임계 돌파용) |
| G | 혜택가 | benefit_unit_price (1개당, 우수고객 혜택가) — 없으면 list_price 정가 fallback |
| **H** | **즉시할인가** | **혜택가 × qty × (1 − 금일 즉시할인%)** ← 우수가 컬럼 제거됨 |
| **I** | **실비** | **= H × (1 − 카드페이백%) − 적립금(H 가격 기준)** ← 시트 수식 가능 |
| J | 행사종료 | 적립 행사 종료일 |
| K~ | 구간1, 구간2, ... | 적립 구간별 (50K/5K 등) |
| 마지막 | URL | 상품 페이지 URL |

> ⚠️ **이전에 있던 "우수가" 컬럼 + "카카오즉시할인가/카카오실비" 분리 컬럼 + 페이백 카드별 컬럼은 모두 제거**. 단일 H/I 로 통합.

**금일 즉시할인% 추출 위치:** 상품 상세페이지의 `<span class="rk5mhl1m rk5mhl0 rk5mhlq _1gvluwy1r">즉시 할인</span>` 영역 (해당 영역의 카드 + % 추출).

### 카드사별 페이백 계수 (5개 카드만 페이백 있음)

| 카드 | 페이백 | 곱하는 계수 |
|------|:-:|:-:|
| 롯데카드 | 2% | × 0.98 |
| 비씨카드 | 1.5% | × 0.985 |
| 삼성카드 | 1% | × 0.99 |
| 하나카드 | 1% | × 0.99 |
| 농협카드 | 1% | × 0.99 |
| (그 외 카드: 현대/국민/신한 등) | 없음 | × 1.00 |

**실비(I열) 계산 흐름:**
1. H (즉시할인가) 구함
2. 즉시할인 적용 카드가 페이백 대상이면 페이백 계수 적용 — 아니면 × 1.0
3. **H (즉시할인가) 기준**으로 적립금 lookup (구간별) — ★ 페이백 적용 후 가격이 아닌 H 기준
4. **I = H × 페이백계수 − 적립금(H 기준)**

> ⚠️ 적립금이 H(즉시할인가) 기준인 이유: 페이백은 카드사가 청구 시 별도 환급하는 것이고, 결제 시점에 실제로 결제되는 금액은 H. 적립 정책은 결제 시점 금액 기준으로 산출됨.
> ⚠️ 카카오페이는 자체 페이백이 없지만 결제 카드가 페이백 대상이면 카드 페이백이 추가 적용된다.
> 단, 슬라이드에 명시된 즉시할인 카드의 페이백을 우선 적용.

### ★ 단순 N% 적립 — 구간 표기 규칙

> ⚠️ 일부 행사("건강식품 브랜드 특별전 10%적립" 등)는 **단순 N% 타입**이라 tier 브래킷이 없다.
> 대신 **{최소금액} 이상 {최대금액} 이하 N% 적립** 형태로 적립 detail 페이지에 표기되어 있다.
> 해당 정보를 직접 적립 detail 페이지 진입해서 추출해야 한다 (행사명 하드코딩 금지 — 매일 행사명 바뀜).

**추출 후 구간1 표기 형식:**
```
{min} ~ {max} N%적립
```
예시:
- `50,000원 ~ 10,000,000원 10%적립` (5만원 ~ 1천만원)
- `50,000원 ~ 2,000,000원 10%적립` (5만원 ~ 200만원, 다른 날)

**추출 절차 (적립 detail 페이지):**
1. 적립 행사 detail 페이지 진입 (Step 2의 evntHPointDtl 링크)
2. table 내 cell 텍스트 검사:
   - 패턴 A: `cells[0] = "X원 이상"` AND `cells[1] = "Y원 이하" 또는 "N%"` → 단순N% 추정
   - 패턴 B: 본문에 `"X원 이상 ~ Y원 이하 N%"` 형태
   - 패턴 C: `"X원 이상 N% 적립 (최대 Y원)"` 형태
3. 어떤 패턴이든 min/max/percent 추출되면 **구간1**에 위 형식으로 표기
4. 기본 적립 계산: 결제금액(H) × N% (단, min ≤ H ≤ max 인 경우만)

**Fallback:** 단순10% 패턴을 찾지 못하면 구간1을 비워두지 말고 `"단순10% (범위 미확인)"` 등으로 표시 → 사용자가 수동 확인하도록 알림

---

### ★ 카드사·카카오페이 할인 받기 위한 5만원 임계 룰

> ⚠️ **최종 결제페이지 1개 구매 가격이 5만원 미만이면 카드사 즉시할인·카카오페이 할인·페이백·적립 모두 받을 수 없다.**
> 임계(5만원) 넘기려면 **여러 개를 구매**해서 결제 합계 ≥ 50,000원으로 만들어야 한다.

**처리 절차 (자동):**
1. 처음에는 `qty=1`로 결제 페이지 진입 → `member_price` (우수가) 확인
2. `0 < member_price < 50000` 이면:
   - `unit_member = member_price / qty` (1개당 우수가)
   - `qty = ceil(50000 / unit_member)` (5만원 넘는 최소 수량)
3. 그 `qty`로 다시 결제 페이지 진입 → 카드 슬라이드/즉시할인가 재확인

> 구현 위치: `cart/check10.py` `_extract_payment_info()` 의 `for attempt in range(2)` 루프 (member < 50000일 때 qty 늘려 재시도)

> ⚠️ 단가가 5만원 넘는 상품은 qty=1로 충분.
> ⚠️ 결제 합계가 5만원 미만으로 끝나면 카드 슬라이드에 할인 카드가 아예 표시되지 않거나, 표시되어도 적용 안 됨 → "할인 없음" 동일

## 부록: 장바구니 담기 절차 (구매하기 → 옵션선택 → 장바구니)

상품 상세 페이지에서 장바구니에 담는 흐름이 일반 쇼핑몰과 다르다.  
**상세 페이지 메인 영역에는 "장바구니 담기" 버튼이 없다.** "구매하기" 액션 버튼 하나로만 진행한다.

> ⚠️ **중요: 상품에 따라 옵션 선택 단계가 있을 수도, 없을 수도 있다.**  
> "구매하기" 누른 다음 무엇이 뜨는지에 따라 **두 가지 경로 중 하나**로 갈라진다. 사전에 페이지를 보지 않고 일률적으로 "옵션 1번 선택"을 가정하면 안 된다.

### 분기 판별 — 구매하기 클릭 후 무엇이 뜨는가

1. **여러 옵션이 묶인 상품 (다중 옵션)**  
   - 팝업/레이어에 `<span class="choice-num title">[선택 1]...</span>`, `[선택 2]...` 등 **`[선택 N]` 라벨이 여러 개** 보인다.  
   - 예: 곡물도감 페이지(`slitmCd=2227834416`)는 [선택 1]~[선택 4]가 같은 페이지에 묶여 있음.
   - → 아래 **경로 A** 따라간다.

2. **단일 상품 (옵션 묶음 없음)**  
   - `[선택 N]` 라벨이 보이지 않거나, 수량/사이즈/색상 등 **단일 상품의 보조 옵션만** 노출된다.  
   - "장바구니" / "바로구매" 버튼이 거의 즉시 활성 상태로 보인다.  
   - → 아래 **경로 B** 따라간다.

판별을 안전하게 하려면 구매하기 클릭 직후 **1~2초 대기 → DOM에서 `span.choice-num.title` 존재 여부 확인** 을 한다.

### 경로 A — 다중 옵션 상품

1. **상품 상세 페이지로 이동.**
2. **`button.btn-purchase` 정확히 한 번 클릭** (이중 클릭 금지).
3. 1~2초 대기 후 팝업의 `span.choice-num.title` 옵션 라벨들을 조회한다.
4. **상품 목록 표의 제품명과 매칭되는 `[선택 N]`** 을 골라 클릭한다.
   - 예: `slitmCd=2227834416` 페이지의 옵션:
     - `[선택 1] 곡물도감 무가당 서리태 콩물 두유` ← 상품 목록 4번 "곡물도감 곡물서리태"
     - `[선택 2] 곡물도감 말차 서리태 콩물 두유`
     - `[선택 3] 곡물도감 식이섬유 가득 비움 두유`
     - `[선택 4] 곡물도감 카무트 귀리 가득 고칼슘 두유`
   - 셀렉터 예시: `span.choice-num.title:has-text("[선택 1]")` (또는 그 라벨이 포함된 클릭 가능 라디오/항목)
5. 옵션 선택 후 같은 팝업의 **"장바구니"** 버튼 클릭.
6. 완료 토스트/알림 닫고 다음 단계로.

### 경로 B — 단일 옵션 상품

1. **상품 상세 페이지로 이동.**
2. **`button.btn-purchase` 정확히 한 번 클릭.**
3. 1~2초 대기. 팝업/레이어가 떴다면 `[선택 N]` 라벨이 없는지 확인.
4. 필요한 보조 옵션(수량/사이즈/색상 등)이 있으면 지정. 수량이 기본 1로 충분하면 그대로 둔다.
5. **"장바구니"** 버튼 클릭.
6. 완료 토스트/알림 닫고 다음 단계로.

> 상품이 다중인지 단일인지는 미리 단정하지 말고, 매번 구매하기 클릭 후 DOM 상태로 판별한다.

### 자동화 시 주의

- **"구매하기" 클릭은 정확히 한 번.** 이중 클릭 또는 빠른 재클릭 금지 — 팝업이 토글되거나 동작이 어긋난다.
- 클릭 직후 가시 모달이 안 보이면 1~2초 대기 후 `display:none` 해제된 `.popup-layerwrap`, `.layer`, 옵션 리스트 컨테이너를 다시 조회한다.
- **`span.choice-num.title` 존재 여부**로 다중/단일 옵션 분기를 결정한다. 존재하지 않으면 옵션 선택 단계 건너뛰고 바로 "장바구니" 클릭.
- 옵션 선택은 **팝업 내부의 항목**을 눌러야 한다. 페이지 본문 하단의 `btn-cart` 클래스 버튼(연관/추천 상품 영역)을 누르면 **다른 상품**이 담기므로 절대 사용하지 말 것.

## 주의사항

- **절대로 상품 목록의 URL을 변경하지 말 것.** 위 테이블에 적힌 URL을 그대로 사용한다.
- **get_page_text가 가장 효율적인 텍스트 확인 방법이다.** 스크린샷 기반 확인보다 get_page_text를 우선 사용한다.
- 페이지 로딩이 느리면 2초 대기 후 다시 시도한다.
- 팝업이 뜨면 닫고 진행한다.
- **상세 페이지의 메인 영역에는 "장바구니 담기" 버튼이 없다.** "구매하기" → 옵션 선택 → 장바구니 순서로 진행한다 (자세한 절차는 위 "부록: 장바구니 담기 절차" 참조).
- 본문 하단의 `btn-cart` 클래스 버튼은 **연관/추천 상품용**이므로 이를 눌러 담으면 안 된다.

세션 분리 기반 자동화를 위해 Playwright MCP를 사용한다. 다음 작업 시 차질이 없도록 설정 절차를 정리해둔다.

### 1. 설치

별도 설치 불필요. `npx`가 자동으로 받아온다. (**Node.js 18+ 필요**)

처음 한 번은 Playwright 브라우저 바이너리를 다운로드한다:

```bash
npx playwright install chromium
```

### 2. settings.json 설정

`~/.claude.json` 또는 `~/.claude/settings.json` 의 `mcpServers` 항목에 추가한다:

```json
{
  "mcpServers": {
    "playwright": {
      "command": "npx",
      "args": ["-y", "@playwright/mcp@latest"]
    }
  }
}
```

### 3. 옵션 추가 (헤드리스 끄기, 격리 모드 등)

옵션을 더 주고 싶으면 다음과 같이 설정한다:

```json
{
  "mcpServers": {
    "playwright": {
      "command": "npx",
      "args": [
        "-y",
        "@playwright/mcp@latest",
        "--browser=chromium",
        "--isolated"
      ]
    }
  }
}
```

#### 주요 옵션 설명

- `--browser=chromium` : 사용할 브라우저 지정 (chromium / firefox / webkit)
- `--isolated` : 매 세션마다 격리된 컨텍스트 사용 (이전 쿠키·세션 흔적 없음 → **다중 계정 자동화에 필수**)
- `--headless` : 브라우저 창을 띄우지 않고 백그라운드 실행 (디버깅 시에는 끄는 것이 좋음)
